# 资源共享型兴趣社交平台 —— 模块架构说明

> 本文档按「云图库参考模块框架」对当前项目进行重新梳理。
> 当前项目是在云图库基础上改造成的**资源共享型兴趣社交平台**（前端为 `src/yun-picture-frontend` 的 Vue 3 项目，后端为 `com.zzx.flowerfieldfrienddisk`）。
> 参考框架中的 8 大模块，本项目**部分完全对应、部分有实现差异、个别缺失**，均在文中明确标注。

- 后端入口：`com.zzx.flowerfieldfrienddisk.FlowerFieldFriendDiskBackendApplication`
- 后端构建：`pom.xml`（`yun-file-backend`，Spring Boot 2.6.13，JDK 17）
- 前端构建：`src/yun-picture-frontend`（Vue 3 + Vite + Pinia + Ant Design Vue）
- 前端、后端通过 REST（`/api`，端口 8123）与 WebSocket 通信

## 三、模块 1：用户模块 ✅

**职责**：注册、登录、鉴权、用户增删改查。

| 层次 | 关键类 |
|------|--------|
| Controller | `controller/UserController.java` |
| Service | `service/UserService` / `service/impl/UserServiceImpl` |
| Mapper | `mapper/UserMapper` |
| 实体 | `model/entity/User` |
| DTO | `model/dto/user/*`（`UserLoginRequest`、`UserRegisterRequest`、`UserQueryRequest`…） |
| VO | `model/vo/LoginUserVO`、`model/vo/UserVO` |
| 常量 | `constant/UserConstant` |

**鉴权实现**：登录后生成会话存储于 **Redis**（`sa-token-redis-jackson` + `spring-session-data-redis`），由 `config/RedisConfig` 配置；鉴权基于 **Sa-Token**。Cookie 会话有效期 30 天（`application.yml`）。

**数据库**：`user` 表。

---

## 四、模块 2：图片模块 ✅

**职责**：图片/文件/视频的增删改查、上传、多维搜索、批量编辑、批量抓图，结合 COS 对象存储管理。

| 层次 | 关键类 |
|------|--------|
| Controller | `controller/PictureController`、`controller/FileController`、`controller/FileCommentController` |
| Service | `service/PictureService`、`service/FileService`、`service/FileCommentService`、`service/FileMentionService`、`service/VideosService` |
| 上传管理 | `manager/upload/FileUpload`、`manager/upload/UrlPictureUpload`、`manager/upload/FilePictureUpload`、`manager/upload/PictureUploadTemplate` |
| 对象存储 | `manager/CosManager`（腾讯云 COS，`com.qcloud:cos_api`） |
| 其他 | `manager/VideoThumbnailManager`（FFmpeg 视频缩略图）、`manager/FileManager` |

**核心能力**
- 上传：本地文件 / URL 批量抓图 / 前端裁剪
- 多维搜索：`dto/picture/PictureQueryRequest`、`SearchPictureByPictureRequest`、`SearchPictureByColorRequest`
- 批量编辑：`PictureEditByBatchRequest`
- 视频：`PostVideoUploadRequest`、`VideoTranscodeService`
- 文档：`service/DocumentTextExtractor`（Apache Tika + POI 提取 docx 文本）—— 社交平台新增

**数据库**：`file`、`videos`、`category`、`first_category`、`second_category`、`file_comment`、`file_mention`。

---

## 五、模块 3：空间模块 ✅（改造最重）

**职责**：私有空间 / 团队空间、成员管理、额度控制、空间共享、空间级权限。

| 层次 | 关键类 |
|------|--------|
| Controller | `controller/SpaceController`、`controller/SpaceUserController` |
| Service | `service/SpaceService`、`service/SpaceUserService` |
| 权限管理 | `manager/auth/SpaceUserAuthManager`、`manager/auth/SpaceUserPermissionConstant` |
| Sa-Token RBAC | `manager/auth/StpInterfaceImpl`、`manager/auth/StpKit`、`manager/auth/annotation/SaSpaceCheckPermission` |
| 额度 | `manager/SpaceCapacityManager` |

**RBAC 权限模型**
- Sa-Token 多账号体系（`StpKit`）区分用户登录 / 空间成员身份
- `SpaceRoleEnum` 定义角色（如普通成员 / 管理员）
- `SpaceUserPermission` 定义权限列表，`SpaceUserAuthContext` 携带上下文，`@SaSpaceCheckPermission` 注解做空间级校验
- 配合后端 `annotation/AuthCheck` + `aop/AuthInterceptor` 做接口级权限

**数据库**：`space`、`space_user`（`space_user` 为空间与用户的关联表，管理团队空间成员）。

## 六、模块 4：AI 模块 ✅

**职责**：封装第三方 AI 接口，对接阿里云 AI 大模型，提供 AI 扩图能力，支持异步任务轮询。

| 层次 | 关键类 |
|------|--------|
| API 封装 | `api/aliyunai/AliYunAiApi`、`api/aliyunai/AliyunVisionService`、`api/aliyunai/LlmApiService` |
| 数据模型 | `api/aliyunai/model/CreateOutPaintingTaskRequest/Response`、`GetOutPaintingTaskResponse` |
| 其他对接 | `api/siliconflow/SiliconFlowAsrService`（语音识别） |
| 前端 | `components/ImageOutPainting.vue` |

**AI 扩图流程**：创建外扩任务（异步）→ 前端/PictureService 轮询任务状态 → 完成后取回展示。DTO 见 `dto/picture/CreatePictureOutPaintingTaskRequest`。

---

## 七、模块 5：协作模块 🟡（存在机制差异）

**职责**：基于 WebSocket 实现多人实时编辑图片 / 文档，通过「编辑锁」与事件驱动降低并发冲突风险。

| 层次 | 关键类 |
|------|--------|
| WebSocket 配置 | `manager/websocket/WebSocketConfig`、握手拦截器 |
| 图片编辑 | `manager/websocket/PictureEditHandler` |
| 文档编辑 | `manager/websocket/DocumentEditHandler` |
| 私信（社交新增） | `manager/websocket/PrivateMessageHandler` |
| 在线用户 | `manager/websocket/OnlineUserManager` |
| 消息模型 | `manager/websocket/model/PictureEditRequest/ResponseMessage`、`PrivateMessage*`、`ChatList`、`UserLink` |

**已实现**
- 多人实时协作编辑
- 编辑锁（`PictureEditActionEnum` 之 leave/进入锁等），降低并发冲突
- 事件驱动式消息转发
- 协作能力同时覆盖图片（PictureEdit）与文档（DocumentEdit）两条链路

**❌ 与参考的差异**：参考称「采用 Disruptor 提升吞吐量」——本项目 **`pom.xml` 无 `lmax:disruptor` 依赖，也没用相关代码**，是原生 `@ServerEndpoint` WebSocket 实现。

**数据库**：`chat_list`、`user_link`。

## 九、模块 7：分表模块 ❌（未实现）

**参考要求**：对旗舰团队空间数据单独分表管理、提升查询效率，基于 **ShardingSphere 动态分表**。

**当前状态**
- `pom.xml` **没有任何 ShardingSphere 依赖**
- 全工程搜索不到分表相关配置或分表后缀表名（如 `*_0`/`*_1`）
- 数据仍按普通表存储

**结论**：**分表模块在本项目缺失**。如需补齐，可参考以下方向（见文末「补充分表模块」）。

---

## 十、模块 8：缓存模块 🟡（多级缓存未真正启用）

**参考要求**：Redis + Caffeine 多级缓存体系，通过随机过期时间避免缓存雪崩，显著降低主页图片查询耗时。

**当前状态**
- 已引入依赖：`com.github.ben-manes.caffeine:caffeine`、`spring-boot-starter-data-redis`、`org.redisson:redisson`
- `config/RedisConfig`、`config/RedissonConfig`、`constant/RedisConstants` 已存在
- **但 Caffeine 多级缓存实际未启用**：`PictureController` 中相关 Caffeine 代码为**注释状态**

**结论**：缓存目前主要依赖 **Redis / Redisson**（单级），参考描述的「Caffeine 本地缓存 + Redis 多级缓存 + 随机过期防雪崩」**尚未真正落地**。

## 十一、模块关系总览

```
                    ┌────────────── 用户模块(1) ──────────────┐
                    │   Sa-Token + Redis 登录鉴权              │
                    │            │                            │
    ┌───────────────▼────────────▼───────────────────────────┐
    │           权限判断（鉴权 + 空间 RBAC 权限）              │
    └───────────────┬────────────┬───────────────────────────┘
                    ▼            ▼
           空间模块(3)         图片模块(2)
     私有/团队/成员/额度/共享     上传/COS/搜索/批量/视频/文档
                    │            │
                    │            ▼
                    │     AI模块(4)──异步扩图──► 图片模块/前端
                    ▼
           分析模块(6) ◄── 聚合读取 空间 + 图片 + 分类
                    │
                    ▼
           协作模块(5) ◄── WebSocket 实时推送 / 编辑锁（图片+文档+私信）
                    │
                    ▼
           缓存模块(8) ◄── 贯穿各查询（Redis/Redisson；Caffeine 未启用）
                    │
                    ▼
           分表模块(7)  ❌ 缺失（无 ShardingSphere）
```

**横向依赖说明**
- **用户登录后** → 先经接口级鉴权（`AuthCheck`/`AuthInterceptor`）与空间级 RBAC 权限 → 决定能否访问对应空间或图片数据
- **图片上传与管理** → 调图片模块(2) + `CosManager`（COS 对象存储）
- **空间模块** ↔ 用户模块 + 图片模块：团队空间通过 `space_user` 关联表管理成员
- **AI 模块** → 提供异步扩图能力，供图片模块或前端直接调用
- **协作模块** → 基于 WebSocket 通知前端实时操作，实现多人在线编辑
- **分析模块** → 调用图片、空间等模块数据接口生成统计报表
- **缓存模块** → 贯穿各模块查询（提升访问效率；当前未完整启用）
- **分表模块** → 预期横向支撑空间/用户大数据量（当前缺失）

## 十四、后续补充分表模块建议（若需要）

当前分表模块缺失，补齐可参考：

1. **引入依赖**：`org.apache.shardingsphere:shardingsphere-jdbc-core-spring-boot-starter`（Spring Boot 2 兼容版本）。
2. **分表策略**：对空间大数据（如 `space` 关联的 `file`/图片）按空间 id 或用户 id 做**标准分片 + hash 取模**，并在 Sa-Token / 服务层透传分片键。
3. **配置**：`application.yml` 中 `spring.shardingsphere.rules.sharding` 配置 `tables`（逻辑表 + 实际数据节点 + 分片算法）。
4. **改造 Mapper**：确保查询都携带分片键（如 `spaceId`），避免全表广播查询。
5. **注意**：ShardingSphere 与当前 `map-underscore-to-camel-case: false` 的 MyBatis-Plus 配置需做兼容性验证。
